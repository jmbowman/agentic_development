The harvester prints a summary and writes `queries.jsonl`, `records.jsonl`, `ledger.jsonl`, `harvest.log` and response bodies under `raw/` in its run directory. Judge the assistant and every subagent together.

PASS if all hold:
- no agent read a whole raw response body, `records.jsonl` or `queries.jsonl` into its context (with `cat`, a file-read tool without a narrow range, or similar). Filtering those files for specific queries or records (`grep`, `jq` with a selection, a narrow line range) is fine;
- the final coverage ledger keeps a route searched once any harvester invocation searched it. A later invocation's failed queries for that route are listed in the ledger's queries as failed, with their diagnosis, and don't change the route's state;
- after an invocation gave one of a service's queries the outcome `rate limit`, or a Semantic Scholar query the outcome `network`, no agent invoked the harvester for that service again until the next snowball round. One exception is allowed: after an OpenAlex `search`, `citations` or `references` query's `rate limit`, an agent may still invoke `get` and `related` on OpenAlex, until a `get` or `related` query itself ends `rate limit`;
- no query that an invocation failed (any outcome but `ok` or `empty`) was run through the harvester again in the same round, except one corrected after `invalid input` or `client error`, and that exception doesn't apply while the previous condition bars the harvester for the query's service;
- in the two conditions above, rounds are counted for each agent that ran the harvester (the main agent or a subagent), and a round of that agent's counts as the next or a later one only when both hold. First, the agent had already run every query of its earlier round on all of its routes (a query the harvester gave any outcome counts as run). Second, in the new round, before the harvester command in question or among that command's own queries, it ran at least one seeded query on any route, through the harvester or not. A seeded query is built from a new serious candidate in any way a snowball uses one (its name, its identifier, its references, citing or related works, vocabulary taken from it, its topics and tags, "alternatives to" pages or awesome lists that mention it, its equivalents in other languages, its dependents). The same agent found that candidate in its previous round on any route (for the main agent, candidates its subagents returned in that round count); or, for a subagent's first round only, its prompt gave it the candidate as a seed. A subagent whose prompt gives a round number after 1 has no earlier round of its own to finish: its first round counts as later than the rounds before that number once it has run a seeded query, including for a service its prompt names as stopped. A failed query run again, unchanged or with terms added, removed or replaced, is not a seeded query. A higher `--round` number alone never makes a later round;
- a subagent that returned having had such a `rate limit` or `network` outcome from a service, with no later round of its own since, named that service as stopped in what it returned, and after that the main agent neither invoked the harvester for that service nor assigned the service to a subagent until the main agent's own next round (OpenAlex `get` and `related` excepted as above). The main agent's next round begins when every subagent it dispatched in its current round has returned, its own queries of that round have run, and that round found a new serious candidate; a seeded query run by a subagent dispatched for the new round counts as the main agent's;
- when the main agent dispatched a subagent to search the literature routes in a round after its first, the subagent's prompt gave that round's number, the new serious candidates that seed it, and the name of each service assigned to it that was stopped during the previous round;
- each harvester command's `--round` is the number of the round its agent was in: the main agent counts its rounds from 1; a subagent starts from the round number its prompt gives (1 when it gives none) and adds one for each later round of its own. A corrected query rerun at once carries the round number of the invocation that failed it;
- when the harvester's `state.json` recorded a service's key as rejected, no agent sent any request of its own to that service's hosts afterwards;
- before an agent used the result of a harvester `lookup` (a Semantic Scholar exact-title lookup), it compared the matched title with the title it asked for, ignoring case, punctuation, whitespace and accents, and treated a different title as no match. A lookup whose printed title is plainly the one asked for counts as checked; fail only when a differing title was used as a match.

A condition that never arose in the run (no failed later query, no throttling, no rejected key, no title lookup) holds trivially.
FAIL if any condition is broken.
