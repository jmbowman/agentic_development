# Sources

The routes to search. Select every route whose trigger matches a signal in the need, and give each selected route a ledger state: searched, excluded with a reason, or unavailable with a diagnosis. "Always" routes are selected for every software need. The first two rows are covered by steps 0 and 4: record them as searched with what you checked, and don't count them toward a quick pass's two searched routes. The `kind` column groups routes: `local` routes are the two covered by steps 0 and 4, and `literature` routes are the ones that the approach trigger selects. A literature route also names a different literature route as its substitute for an outage.

Catalogs are used through their websites or APIs only. Never install a catalog's own finder skill or CLI to search it.

## Keyword collisions

Every literature source returns unrelated fields for an ambiguous word: "comprehension" finds taxonomy, "diff" finds diffusion models and infections, "agent" finds ecology, "state machine" finds physics. Pair the ambiguous word with a software-specific term in the same query, and read titles before opening results.

## Rate limits

A rate limit belongs to a service, not a route, and covers everything this run sends to that service: your requests and your subagents' together. Several routes share one service: the GitHub search routes share GitHub's search budget, and arXiv's API and listing pages share arXiv's limit. Some services count every machine under your control as one client (arXiv says so), so other runs sharing your machine or network share the limit too.

- Keep within the limit below. Send one request at a time to a service unless it states a concurrency allowance (only Crossref does); a rate per second isn't one.
- Give each service to one agent at a time: when you split work across subagents, assign services, not routes, and route every other request to that service (the OpenAlex lookups that find legal copies, a substitute search, arXiv preprints at the end of a snowball round) through the agent that holds it, or make them yourself between its turns.
- After a rate-limit response, wait as long as the service says (a `Retry-After` header or the error's message), or 15 seconds if it says nothing, before your one retry.

**Default:** where no limit is stated, at most one request every 3 seconds, one at a time.

**User agent:** for requests you send yourself with a tool that can set headers (`curl`, for example), send a `User-Agent` that names the skill and a way to reach its maintainers, such as `prior-art-search agent skill (+https://github.com/jmbowman/agentic_development)`. crates.io requires one, so send its API requests that way; Crossref and Wikimedia ask for one. Your agent's own web search and fetch tools set their own, which is fine. Never put the developer's address in it; a contact address goes to a service only through its setting (such as `crossref.mailto`).

Stated limits, with where they are stated (read 2026-11-05):
- **arXiv:** no more than one request every three seconds, over a single connection, across all machines under your control ([terms of use](https://info.arxiv.org/help/api/tou.html#rate-limits)). Its listing pages ask for a 15-second crawl delay (its robots.txt), which also covers **Venue program pages** on arXiv; other venue pages have none stated, so use the default.
- **OpenAlex:** 10 requests a second without a key and 30 with a free key, within a daily budget that a key raises from about $0.10 to $1; searches cost more than lookups, and a search with more than 5 boolean operators is limited to 1 a second without a key ([authentication and rate limits](https://help.openalex.org/api/authentication/)).
- **OpenAIRE:** about 7,200 requests an hour without a key (its `x-ratelimit-limit` response header).
- **Semantic Scholar:** anonymous requests share 1,000 a second across all anonymous users and are throttled further under heavy use ([API page](https://www.semanticscholar.org/product/api)); in practice anonymous calls often get 429, so space them 8 seconds apart.
- **Crossref:** 5 requests per interval with 1 at a time in the public pool, 10 with 3 at a time in the polite pool; the interval is in the `x-rate-limit-interval` header ([access and authentication](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/)).
- **Zenodo:** 30 requests a minute (its response headers), and its robots.txt disallows `/api`, so read that again before use.
- **libraries.io:** 60 requests a minute per key ([API documentation](https://libraries.io/api)).
- **crates.io:** for its API, a maximum of 1 request a second, with a user agent that identifies the application and how to reach its maintainers; its sparse index and static downloads (`static.crates.io`) have no rate limit ([data access policy](https://crates.io/data-access)). Use the index and the crate download for a known name, and the API only for keyword search.
- **GitHub repository search**, **GitHub topics**, **GitHub topics for agent skills** and the GitHub searches behind **Awesome lists** and **Awesome lists for agent skills**: 30 search requests a minute when authenticated, 10 when not; **GitHub code search** needs authentication and allows 10 a minute ([search API](https://docs.github.com/en/rest/search/search)). **Anthropic's skills repo** is read through the GitHub contents API or a clone, within GitHub's general API limits.
- **ecosyste.ms:** 5,000 requests an hour without a key (its response headers).
- **AUR:** a 2-second crawl delay (its robots.txt).
- **Homebrew formulae**, **nixpkgs**, **Claude Code plugin marketplaces** and **aitoolnet.com**: none stated, so the default applies; download the index file (or sitemap) once per run and search it locally, and read any further pages at the default.
- None stated, so use the default: **GitLab and Codeberg search**, **npm**, **PyPI**, **Language registries** (unless the registry states one), **LibHunt**, **Skill directories**, **MCP Registry**, **PulseMCP**, **papers.cool**, **Hugging Face papers** and **Europe PMC**.
- Searched through your agent's web search tool, not by direct requests, so no route limit applies: **Cross-language equivalents**, **General web search** and **Hosted services**. **alternativeto.net** isn't queried at all (see its row).

## Access settings

An optional file, `.config/prior-art-sources.toml` in the host repo, holds keys and contact addresses; the template is [settings.example.toml](settings.example.toml), and a developer copies it there and fills it in. Read it only when git ignores it, as [SKILL.md](../SKILL.md#access-settings) says; if git doesn't, ask the developer there whether to add `.config/prior-art-sources.toml` to the host repo's `.gitignore`. These are the settings and the routes that use them:

- `openalex.api_key` (optional): OpenAlex. A free key gives a larger daily budget. Without one, search can be paused under load (an HTTP 503 whose message names the key), while DOI and citation lookups still work.
- `librariesio.api_key` (required): libraries.io. Without a key the route is unavailable ("setting not set") and isn't searched, which blocks **build** when the route is triggered.
- `crossref.mailto` (optional): Crossref. A contact address puts requests in its faster pool.
- `semanticscholar.api_key` (optional): Semantic Scholar. A key lifts the rate limits.

A route with no setting here needs none.

## When a route fails

Retry once. If it still fails, diagnose why (authentication, rate limit, network, no such tool, setting not set) and record the route as unavailable with that diagnosis. A route whose setting is required and not set needs no request: record it unavailable ("setting not set") without trying it. A route whose trigger names a condition about the environment (GitHub code search "when authenticated", nixpkgs "when a brotli decompressor is installed") and whose condition fails is excluded, with the reason "condition unmet", not unavailable. A literature route that is unavailable has a named substitute in the table. When the substitute was searched, the outage no longer blocks a **build** verdict, though you list the route under "Could not verify"; when a route and its substitute are both unavailable, **build** stays blocked. For any other route, an unavailable route blocks only a **build** verdict. A route that is still throttled after its retry with no key set is unavailable with the diagnosis "rate limit, no key set". A search that an anonymous client can't run (OpenAlex answers a paused search with HTTP 503 and a message naming the key) is the same case.

A 403 from your agent's fetch tool may be the tool, not the site: aitoolnet.com blocked one fetch tool but answered `curl` with an honest user agent. Retry once with `curl` and the skill's user agent (see [Rate limits](#rate-limits)), but stop at a challenge page ("Just a moment…"), which is an access control you must not work around.
