# Prior art: doctrine, a Rust harness for agentic engineering (2026-11-13)

- **Origin:** a closer reading of one candidate from [the task-management note](2026-11-12-task-management-for-humans-and-agents.md), which classified [doctrine](https://github.com/davidlee/doctrine) as "borrow ideas" for its priority model. This note covers the rest of the project.
- **Effort:** a read of its design docs and the relevant code at d3c19d7, not a search; nothing was installed or run.

## What it is

[doctrine](https://github.com/davidlee/doctrine) has the same aim as this repo: replace prose instructions to coding agents with deterministic guardrails, and keep intent, decisions and evidence in repo files. It ships as a Rust CLI with skills for several agent harnesses. Every change is a "slice" that moves through scope, design, plan, phases, audit, reconcile and close, and the project records specs, ADRs, RFCs, review ledgers, scoped memories and friction observations as TOML and Markdown under `.doctrine/`.

Scale and adoption, as of 2026-11-13: created 2026-06-30; about 8,300 commits and 55 releases, all under one author; about 288,000 lines of Rust; 3 stars and no forks. Its own corpus holds 571 slices, more than 800 review ledgers, 48 ADRs, 35 RFCs and 879 friction observations.

**Not adopted:**
- it brings its own change process, which would compete with LID, and edits specs after the code rather than before;
- its code is GPL-3.0-only (its `.doctrine/`, `plugins/` and `install/` files are MIT);
- `install` writes `CLAUDE.md`, `AGENTS.md`, `.claude/settings.json`, `.mcp.json` and user-level Codex config;
- its skills route to a library only its binary can serve, against tenet 7, and a gitignored boot file is imported into the committed `CLAUDE.md`, against tenet 9.

**How much weight to give it.** The project measures its own process and publishes negative results, which makes it unusually informative. But every finding below is the self-report of one project, built without a prior-art step or a spec-to-code arrow like LID, and much of its machinery is documented ahead of its enforcement: the slice state machine refuses only two kinds of move, and its authority model and approval roles are self-declared. Treat the ideas as hypotheses to test on this repo's own process, not as evidence.

## Claude Code behaviors it reports

From its harness field notes (`rfc/018`), citing Claude Code 2.1.198. Re-probe before relying on any of them:
- PreToolUse hooks fail open; only exit status 2 blocks;
- SubagentStop fires before the worktree is removed;
- a hooks edit in `settings.local.json` takes effect without a restart;
- Workflow agent steps have the Agent tool removed;
- its notes contradict each other on which base `isolation: worktree` uses.
