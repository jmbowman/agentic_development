# Prior art: catalogs and paper sources that agents can read (2026-11-04)

- **Effort:** full method, because the source list shapes every later search the skill runs, and a bad route either wastes a lookup each time or gives a false sense of coverage.
- **Already known:** the developer knew aitoolnet.com had returned HTTP 403 in earlier runs (issue #97). They named two earlier notes in which research papers were especially informative: [review and comprehension burden](2026-10-27-review-and-comprehension-burden.md) and [change presentation](2026-10-30-change-presentation.md). They accept manual downloads of particularly useful papers through legal services.

## Need and criteria

| Requirement | Underlying need |
|---|---|
| Find catalogs, directories and registries of software, AI and agent tools, skills, plugins and MCP servers | Surface good candidates that the existing routes (forge search, package registries, awesome lists, web search) miss |
| The catalogs must be readable by an agent | A route that fails adds a failed lookup to every search |
| Add routes for research papers and similar literature | Needs about an approach or technique ("what helps achieve this objective") are answered by studies, not repositories |

**Hard criteria:** reachable by `curl` or a web fetch without credentials or a browser; machine-readable (API, static HTML, sitemap or downloadable dataset); the route's robots rules and terms permit an automated read; paper routes obtain full text only by legal means (open access, author or institutional copies, or a copy the developer obtains lawfully and supplies).

**Preferences:** adds good candidates the existing routes miss, ranked by that and not by catalog size; works for several needs, not one; stable query pattern.

## Verdict

**Blend:** keep the existing routes, and add the catalogs and paper routes marked *add* or *conditional* below. This isn't a build verdict. The work is an update to `references/sources.md` and the skill's specs.

Method: read-only research subagents probed each source on 2026-11-04 with `curl` and a descriptive user agent, one retry on failure, no credentials. A first round judged each source on a few needs; the developer objected that a list for general software investigations can't rest on one topic, so a second round re-judged every source against 18 topics: the eight earlier notes' topics, six broad software topics (dependency risk, flaky tests, configuration drift, LLM-agent evaluation, reproducible builds, API evolution) and four upcoming research areas. The tables show the verdicts after the second round. The raw probe outputs were not kept. The main agent re-verified the aitoolnet and Glama findings itself (below). Every other finding comes from a subagent's probe and is tagged *subagent-probed*. Relevance was judged from titles and listing lines, not by opening every entry. Unique-candidate counts are approximate, because each baseline used a fixed set of phrasings, and some "unique" finds were vocabulary the baseline lacked, not coverage it lacked. The terms of use of the catalogs' data weren't read in full.

Four findings from the broader sample:
- The most useful new routes are distro index dumps, which carry descriptions and licenses and let the agent grep with its own patterns. Homebrew is the practical one.
- The catalogs added serious candidates the baseline's top results lacked on 12 of the 18 topics (review burden, change presentation, wrap-up, dependency risk, flaky tests, config drift, reproducible builds, API evolution and three of the four upcoming areas), and none on five (prior-art skills, docs sites, knowledge bases, skill evals, agent evaluation).
- The baseline wins on agent-skill topics and is weak on config drift, reproducible builds and multi-word phrases.
- Part of the catalogs' win is vocabulary. "Semantic diff" matched 0 Homebrew formulae while difftastic and dyff need other words, and a `gh` query for "yaml diff" finds dyff. Catalogs mostly help when the baseline's wording misses, so the skill should say to vary synonyms.

**Reliability is part of the verdict.** The first round found OpenAlex and Semantic Scholar usable. The second, from the same IP, found OpenAlex's keyword search failing about 75% of the time and Semantic Scholar's relevance search returning 429 for 40 minutes, while their citation and lookup calls kept working. The skill's rule (retry once, then record the route as unavailable) therefore applies often to these routes, and the paper routes need enough substitutes that one outage doesn't leave a triggered route unsearched: arXiv, OpenAIRE and Semantic Scholar bulk search cover each other's gaps.

**Keyword collisions** dominate every source: "comprehension" returned bee taxonomy (Zenodo), "diff" returned diffusion and differentiation (arXiv) and C. diff infections (CORE), "agent" returned ecology and finance agents, "state machine" returned physics preprints, "handoff" returned CDMA handoffs. A query needs a software-specific term beside the ambiguous word.

**What the 18-topic calibration found that the earlier notes lack.** The notes on prior-art skills, reference clones, docs sites, knowledge bases, wrap-up skills and skill evals cite no papers at all, and the review and change-presentation notes cite many but not these (checked by string search). Examples, as leads only, not yet read: coding agents that reuse code or reinvent it (arXiv 2609.35357); progressive disclosure in an LLM-maintained wiki (2607.04576, 2607.17598); evaluating AGENTS.md files (2602.11988); handoff debt and compaction (2606.02875, 2610.31710); file ordering in code review (2609.04207); diff presentation work (2607.29516, 2510.12487, 2212.11077); agent-skill evaluation (2606.17819); and the older diff-tool lineage reached through ChangePrism's reference list on Semantic Scholar. Some topics are thin in the literature: dependency cooldowns, configuration drift, shipping compiled helpers with skills, and the division of labor between LLMs, code and people returned little, and need web and GitHub search.

**How papers fit the method.**
- A paper counts as a *serious candidate* when its abstract page shows it addresses the approach question with some evidence.
- Classes are **borrow ideas** or **reject**. **Adopt** and **build on** apply only to software that implements a technique.
- There's no source to verify, so a paper's claims carry *paper-reported*, not *verified in source*. Each paper also records how much was read (*read in full*, *read in part*, *abstract only*, *not retrievable*), its evidence strength (experiment, observational study, qualitative study, vendor report, untested proposal) and its review status (peer-reviewed, preprint, thesis or report). Claims from abstract-only or preprint-only papers are capped.
- Snowball through citations: backward (`referenced_works`), forward (`cites:`), related (`related_works`, recommendations), then new vocabulary, then arXiv by date.
- Full text only by legal means: the open-access location from an OpenAlex DOI lookup, the arXiv PDF, an author or institutional copy, or a copy the developer lawfully obtains and drops in the project. A paper that looks decisive but is paywalled goes on a "worth retrieving manually" list, with its DOI, why it matters and the legal ways to get it; until the developer supplies it, it stays *abstract only*. Shadow libraries and unauthorized mirrors are never used.

## Limitations checked in source

None of these routes is a code candidate, so nothing here is *verified in source*. Reachability findings are *observed 2026-11-04*, by the main agent for aitoolnet and Glama's API and by subagents for the rest.

Verified:
- aitoolnet's apex redirects to `www`, which serves `/`, `robots.txt` and the 48,060-entry sitemap to `curl` (main agent, 2026-11-04).
- aitoolnet's robots.txt disallows search parameters and names the sitemap (same).
- Glama's API returns 401 without a key (same).

Could not verify:
- The data terms of Homebrew's and nixpkgs' index files, LibHunt, PulseMCP and Glama's attribution requirement. Each should be read before bulk caching or quoting. arXiv's one-request-per-3-seconds rule was recalled by a subagent, not re-read.
- Terms read on 2026-11-05 for the services that take settings: [OpenAlex](https://help.openalex.org/access/pricing/) (data released under CC0; a free key raises the daily budget from $0.10 to $1; the terms-of-service PDFs weren't read), [Crossref](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/) (public pool 5 requests per interval and 1 concurrent, polite pool 10 and 3; most metadata may be used for any purpose, abstracts may be copyrighted), [Semantic Scholar](https://www.semanticscholar.org/product/api/license) (non-transferable, terminable license; credit required in published materials; key not to be disclosed beyond the organization; data under its own licenses such as CC BY-NC) and [libraries.io](https://libraries.io/terms) (data CC BY-SA 4.0). Unpaywall's [terms of service](https://www.unpaywall.org/legal/terms-of-service) were read in full from a saved copy (the page needs JavaScript): see its row above. Its separate API page, which might state a data license or rate limit, remains unread. OpenAlex says [Unpaywall now runs on OpenAlex's database](https://help.openalex.org/access/unpaywall/), and an OpenAlex DOI lookup returned the same open-access fields in two checks (a closed paper and a green open-access one), without a key or email.
- OpenAlex's per-topic precision: its keyword search was throttled about 75% of the time, so it is mostly unmeasured. Its verdict rests on reliability and on the lookup calls that did work.
- OpenAIRE's exact endpoint and recipe, which the skill row has to confirm when it is written.
- Relevance in the second round was judged from titles and listing lines, not from opening each entry. Papers named as leads are unread.
- Crossref's `type` filter, and PulseMCP's robots rules under a strict reading of its second `*` group.
- Papers from the two earlier notes that remain abstract-only.
